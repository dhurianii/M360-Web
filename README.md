# Money360 — Marketing Site

Static marketing site for [Money360](https://moneylizer.com), served from the project root. All pages share a header, footer and mobile nav that are injected by `assets/js/partials.js`, so changes to chrome happen in one place.

## Folder map

```
money360-site-fixed/
├── index.html              Landing — hero carousel (4 slides), cube, sources panel
├── blogs.html              Facebook feed
├── faqs.html               Embedded FAQ accordion (iframe)
├── rnd.html                R&D overview
├── privacy.html            Privacy policy (iframe → legal-privacy.html)
├── terms.html              Terms of use (iframe → legal-terms.html)
├── data-policy.html        Data policy (iframe → legal-data.html)
├── package.json
├── assets/
│   ├── css/                Main + responsive stylesheets
│   ├── js/                 Shared header/footer injector + mobile nav
│   ├── images/             Logo, favicons, PWA icons
│   ├── video/              Hero videos (first-slide, demo)
│   ├── content/            HTML fragments loaded as iframes
│   │   ├── faqs.html
│   │   ├── sources.html          (slide 3 of the carousel)
│   │   ├── cube.html             (slide 4 — 3D financial cube)
│   │   └── legal-*.html          (generated by the build script)
│   └── manifest/           PWA web manifest
└── scripts/
    └── build-legal.js      Fetches the upstream MegaGraphs docs and
                            regenerates assets/content/legal-*.html
```

## Local preview

This is a static site — open `index.html` directly, or serve the repo root with any static server:

```bash
python -m http.server 8000
# then visit http://localhost:8000/index.html
```

## Updating the legal pages

The three legal pages pull from the upstream MegaGraphs docs at build time. To refresh them after a policy change:

```bash
npm run build:legal
```

This runs `scripts/build-legal.js`, which fetches the three upstream docs, extracts the policy `<article>` from each, and writes the cleaned output into `assets/content/legal-{privacy,terms,data}.html`. No external npm dependencies — the script uses only Node built-ins.

## Notes

- `assets/content/sources.html` uses `<base href="../">` so its internal relative links resolve to the project root. Don't change that depth without also updating the `<base>` tag.
- The web manifest at `assets/manifest/site.webmanifest` uses root-relative icon paths (`../images/...`) because it lives one level below the icons.
